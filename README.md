# Boss海投

一个跑在自己浏览器里的 BOSS 直聘批量投递工具：按关键词采集岗位、按规则筛掉噪音、自动打招呼并发送你写好的自我介绍。

不登录第三方服务器，不接管账号密码，全部操作都在你本机已登录的 Chrome 里完成。

## 为什么单独做一个

现成的批量投递脚本大多有三个问题：

1. **要你的账号密码或 Cookie**，本质是把登录态交给别人。
2. **点了按钮就当投递成功**，实际上被站点的频率弹窗拦下，一天下来一个也没投出去。
3. **按选择器硬编码**，站点改一次类名就全线失效，且不告诉你是哪一步坏了。

这个工具针对这三点分别做了处理：只通过 CDP 驱动本机浏览器、每一步都回读页面状态验证、把所有选择器集中在一个文件里便于修复。

## 环境要求

- Node.js >= 22（用到全局 `WebSocket` 与 `fetch`，无任何第三方依赖）
- 一个可以用 `--remote-debugging-port` 启动的 Chromium 内核浏览器

## 快速开始

### 1. 用调试端口启动浏览器

先完全退出浏览器，再用调试端口启动，并**手动登录**目标站点：

```bash
# Windows
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222

# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222
```

登录这一步必须自己来。工具不接触也不保存任何凭据。

### 2. 配置

```bash
cp config.example.json config.json
cp message.example.txt message.txt
```

`config.json` 里改这几项就够：

| 字段 | 说明 |
| --- | --- |
| `cdp` | 调试端口地址，默认 `http://127.0.0.1:9222` |
| `city` | 城市编码，从站点搜索结果的 URL 里抄 |
| `keywords` | 搜索关键词列表，逐个搜索后合并去重 |
| `keepPattern` | 岗位标题**命中**这个正则才保留 |
| `dropPattern` | 岗位标题**命中**这个正则就丢弃（`dropExemptPattern` 可豁免） |
| `limits.perRound` | 单轮最多投递几个 |
| `limits.roundIntervalMin` | 两轮之间等待多少分钟 |

`message.txt` 写你要发出去的自我介绍。文件里如果还留着 `[占位符]`，程序会拒绝启动。

### 3. 跑

```bash
node src/cli.mjs status     # 看历史统计
node src/cli.mjs collect    # 只采集和筛选，不投递
node src/cli.mjs apply --dry        # 预演，看会投哪些
node src/cli.mjs apply --limit 10   # 真投 10 个
node src/cli.mjs greet --limit 40   # 给会话里还没发过话术的人发
node src/cli.mjs run --rounds 5     # 采集→投递→发话术，循环 5 轮
```

## 工作流程

```
搜索关键词 ──▶ 抓岗位卡 ──▶ 标题规则筛选 ──▶ 去重
                                              │
                     ┌────────────────────────┘
                     ▼
              打开岗位页 ──▶ 点「立即沟通」
                              │
                     ┌────────┴────────┐
                     ▼                 ▼
              按钮变「继续沟通」    弹出频率提示
                  = 投递成功         = 需确认后重试
                     │                 │
                     └────────┬────────┘
                              ▼
                      打开会话 ──▶ 判断是否已发过
                                      │
                              未发 ──▶ 输入话术 ──▶ 发送 ──▶ 回读校验
```

## 踩过的坑

这些都是实测出来的，写在代码注释里也写在下面，方便你改的时候少走弯路。

**点按钮不等于投递成功。**
当账号接近当日沟通上限时，每次点击都会弹出一个提示框，这次点击不会产生任何投递。脚本如果只判断"点到了按钮"就会误报成功。正确做法是点完之后回读按钮文案：变成「继续沟通」才算投递成功。

**弹窗要能关，关不掉就是该停了。**
提示框里通常有个确认按钮，点掉之后**再点一次**立即沟通，有时还能成功。但如果确认按钮点了没反应，就是当天额度真的用完了，应该停止而不是继续空转。

**会话列表是分页的。**
列表初始只渲染几十行，早期的会话不在 DOM 里。找会话之前必须先滚动加载，否则永远匹配不到。

**会话行不能按属性定位。**
行上的 `d-c` 属性在多行之间重复，用属性选择器永远只会命中第一行。只能按 DOM 索引定位。

**发送后索引会变。**
发完一条消息，该会话会跳到列表顶部，后面所有行的索引整体前移。所以遍历要从后往前，否则会重复发或漏发。

**输入框是富文本编辑器。**
直接改 `innerHTML` 或 `execCommand` 会被编辑器忽略。可靠的路径是：聚焦 → 全选 → 真实键盘 Ctrl+A → Backspace → `Input.insertText`。而且输入后要等约 1 秒再回读，太早读到的是半截。

**回读文本不能逐字比较。**
编辑器会把空行渲染成额外的换行标签，`innerText` 还原出来比原文多换行符。比较前应该把所有空白字符全部去掉，并且只比对首尾片段，不要比全长。

## 目录结构

```
src/
  cli.mjs        命令入口
  config.mjs     配置加载与校验
  cdp.mjs        CDP 客户端、文本输入、比较工具
  selectors.mjs  所有页面选择器（站点改版时只动这里）
  collect.mjs    岗位采集与标题规则筛选
  apply.mjs      投递流程与弹窗处理
  greet.mjs      会话遍历与话术发送
  store.mjs      去重存储与轮次记录
docs/
  selectors.md   选择器对照与修复指引
data/            运行时生成，已在 .gitignore 中
```

## 站点改版了怎么办

先跑 `node src/cli.mjs collect`。如果输出 `采集 0`，说明列表选择器失效；如果采到了但 `apply` 报 `no apply button`，说明详情页选择器失效。改 `src/selectors.mjs` 里对应的那一行即可，其余代码不用动。

`docs/selectors.md` 里有每个选择器的用途和它在页面上的位置描述。

## 使用须知

- 这个工具只是把重复点击做得更快，**不会提高你的匹配度**。投得多不等于面得多，筛选规则要自己调到合适。
- 站点的频率限制是真实存在的，`config.json` 里的节奏参数是保守值，调快会让账号被限制。
- 批量发送相同话术会被识别为骚扰，请自己把握措辞和数量。
- 请在你自己的账号上使用，并遵守目标站点的用户协议。作者不对使用后果负责。
